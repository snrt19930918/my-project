# 智慧建筑二装服务管理系统产品需求文档（V1.4）

> 版本：V1.4　更新日期：2026-10-29
>
> 事实基准：微信小程序原型 `fitout-process`、Web 管理后台原型 `fitout-admin` 及两份主规格文档。
>
> 口径说明：原型与本文不一致时以原型为准；原型未实现或未模拟的规则统一标注「原型未实现」，后续功能标注「后续规划」。本文同时给出面向开发的字段、状态机、权限校验与接口契约（见附录 A–D）。

## 一、业务概述与核心定义

### 1.1 业务背景与系统目标

传统二装服务依赖线下人工流转，存在节点不透明、权责边界模糊、数据分散难追溯、跨岗位协同效率低等问题。本系统以线上标准化管控为目标，采用「微信小程序 + Web 管理后台」双端架构，覆盖二次装修施工、审图代办、申报代办三类服务，实现全业务节点线上流转、角色权责清晰、数据全链路可追溯、超时预警与结束服务可控。

### 1.2 终端架构说明

- **微信小程序端**：客户与内部员工的统一业务入口。按手机号自动识别身份，客户进入客户工作台，员工进入员工工作台；员工可按岗位权限处置节点。小程序端是业务办理与节点操作的主入口。
- **Web 管理后台**：系统管理员与内部管理岗位的管控端，承载驾驶舱、项目点位、账号与岗位权限、服务单全量管理与审计、流程编排、通知与超时、统计报表等管理能力。
- **数据同源**：两端共用同一套服务单、节点、合同、收款、会签与状态口径；同一功能在两端必须具备一致的业务规则与校验结果。

### 1.3 核心业务对象定义

- **建筑项目**：二装服务单的归属载体，指商业广场、写字楼等建筑主体。项目名称以地图服务拉取的官方名称为准，支持补充别名；后台可配置项目类型、地址、状态与专属服务团队。
- **服务单**：客户单次二装服务需求的业务单元，承载施工位置、面积、服务内容、节点流转、合同、收款、文件、会签与操作记录。
- **服务内容**：施工、代办审图、代办申报三类能力的组合。下单时以「施工 / 仅代办」为主选择，代办审图与代办申报可多选。
- **合同**：报价员确认合同后生成，服务项分为仅代办、仅施工、完整施工代办三类。同一服务单可签订两份合同（仅施工 + 仅代办），也可一次签订完整施工代办合同。
- **合同收款**：合同签订后生成的并行收款支线。财务人员可多次填写累计收款比例与本次收款金额，单份合同收至 100% 后该合同收款完成。
- **结束服务会签**：员工在任一处置节点发起的终止服务申请，须经项目经理与报价员会签确认后生效，形成结束服务记录。
- **节点版本**：每个节点每次提交生成版本记录，包含操作人、时间、版本号、表单内容与附件。

### 1.4 业务流程总览

服务单主流程：

```text
创建 →（评估指派，可选）→ 图纸深化 → 审核 → 确认合同
     →（审图，可选）→ 施工 →（申报，可选）→ 验收办结
```

并行支线：**合同收款**。合同签订后即生成收款项目，与施工/代办服务并行推进。

服务单最终办结条件：**服务支线完结 + 全部已签合同收款 100%**。

三类合同对应节点：

| 合同服务项 | 服务节点 |
|---|---|
| 仅施工 | 施工 → 验收办结 |
| 仅代办 | 审图 / 申报（按所选代办项生成）→ 代办服务完结 |
| 完整施工代办 | 审图（如选）→ 施工 → 申报（如选）→ 验收办结 |

## 二、角色、岗位与权限

### 2.1 角色与岗位

| 角色/岗位 | 端侧 | 核心定位 |
|---|---|---|
| 客户（业主） | 小程序 | 发起服务单、查看进度、取消未开始深化的服务单 |
| 绘图员 | 小程序 / Web | 图纸深化、工作量拆解、提交图纸 |
| 项目经理 | 小程序 / Web | 评估指派、图纸审核、施工量更新、提交验收、结束服务会签 |
| 报价员 | 小程序 / Web | 确认合同、补充第二份合同、结束服务会签 |
| 财务人员 | 小程序 / Web | 合同收款进度更新、金额查看 |
| 代办人员 | 小程序 / Web | 审图、申报代办执行与凭证上传 |
| 施工人员 | Web 岗位配置（预留） | 后台可维护岗位与项目团队；当前小程序施工节点由项目经理执行，未开放独立施工人员视角 |
| 系统管理员 | Web | 项目、账号、岗位、流程、通知、服务单、报表的全量管理与审计 |

小程序端当前提供客户、绘图员、项目经理、报价员、财务人员、代办人员 6 类角色视角。

### 2.2 各角色核心权责

- **客户**：创建服务单；查看本人工单进度、合同与收款比例；在绘图员尚未开始深化时取消服务单。客户不参与内部节点推进，不展示「待处理」概念，进行中统一显示「服务中」。
- **绘图员**：接收图纸深化节点，上传深化图纸与工作量清单；工作量清单按「系统—部件」结构填写新装、拆除、移位数量。
- **项目经理**：对客户自定义项目执行现场勘验并指派绘图员；审核深化图纸与工作量；更新施工量；提交验收；作为结束服务会签人。
- **报价员**：确认合同（可两次签订）；确认合同金额与附件；作为结束服务会签人。
- **财务人员**：按合同更新累计收款比例与金额；可查看完整合同金额与收款金额；不参与主流程节点推进。所有具备财务权限的用户共享收款处置权，不按个人独占收款节点，均可看到「待收款 / 已收讫」并按同一口径完成收款。
- **代办人员**：执行审图、申报事项并上传代办凭证。
- **系统管理员**：维护项目点位与专属团队、员工账户、岗位与节点处置权限、流程分支、通知与超时规则；查看全量服务单、节点版本与报表。

### 2.3 身份匹配与切换

- 微信授权登录以手机号为唯一匹配字段。
- 手机号匹配员工账户时进入员工工作台；匹配客户账户时进入客户工作台。
- 同一手机号同时具备客户与员工身份时，默认进入客户工作台，并提供切换入口（原型以角色 Tab 模拟，手机号匹配与身份切换未模拟）。
- 客户首次登录且无账户资料时，进入信息补全页，填写客户名称（企业名称）与电子邮箱；手机号来自微信授权，不在页面重复填写。
- 员工登录后按岗位权限加载可处置节点与待办。

### 2.4 节点处置权限模型

- 节点不直接绑定「处置岗位」，而是绑定「处置权限」，权限名称按节点操作命名，如「审核处置权」「合同处置权」。
- 系统按「员工岗位是否绑定该节点处置权限」判断是否可处置该节点。
- 岗位可在 Web「岗位配置」中自定义并绑定多个节点处置权限。
- 项目专属团队用于预选下一节点接收用户；项目未配置对应岗位人员时，流转至该岗位共享工作池。

本期内置岗位与节点权限映射：

| 岗位 | 绑定节点处置权限 |
|---|---|
| 绘图员 | 创建、图纸深化 |
| 项目经理 | 评估指派、图纸审核、施工、验收办结；另承担结束服务会签 |
| 报价员 | 确认合同；另承担结束服务会签 |
| 财务人员 | 合同收款 |
| 代办人员 | 审图、申报 |
| 施工人员 | 施工（预留，当前由项目经理执行） |

### 2.5 数据权限与金额脱敏矩阵

| 数据类型 | 客户 | 员工 | 财务人员 | 系统管理员 |
|---|---|---|---|---|
| 本人/本单业务数据 | 仅本人服务单 | 权限范围内 | 财务可见服务单 | 全量查看 |
| 合同总价 | 脱敏 | 脱敏（报价员确认合同表单除外） | 完整 | 脱敏 |
| 收款金额/大写金额 | 脱敏 | 脱敏 | 完整 | 脱敏 |
| 收款比例 | 可见 | 可见 | 可见 | 可见 |
| 客户手机号 | 仅本人（脱敏） | 本单可见（脱敏） | 本单可见（脱敏） | 脱敏查看；完整号码查看与留痕为「原型未实现」 |
| 企业邮箱 | 仅本人 | 权限范围内 | 权限范围内 | 权限范围内 |
| 结束服务会签记录 | 仅查看结果与原因 | 本单可见 | 本单可见 | 全量查看 |

金额脱敏统一规则：除财务人员视图与报价员「确认合同」表单外，任何页面不得展示合同总价、收款金额及大写金额；金额位置显示「金额已脱敏」或「总价已脱敏」，比例保留。

> 原型现状：所有端客户手机号均以 `138****2211` 形式展示，未提供完整号码查看入口；正式实现按上表补齐权限、授权与留痕。

### 2.6 项目团队与共享池

- 建筑项目可配置绘图员、项目经理、报价员、财务人员、代办人员、施工人员等专属负责人。
- 节点流转优先匹配项目配置人员；项目经理评估指派时可直接选择绘图员。
- 项目未配置对应岗位人员时，节点进入该岗位共享工作池：原型仅支持项目经理评估指派与管理员分派，员工主动拾取为「后续规划」。
- 员工账户停用后，其名下待办退回共享工作池（原型仅展示提示文案，回流逻辑为「原型未实现」）。
- 临时项目默认不配置专属团队，按共享池规则流转；后台完善配置后，在途服务单同步适用新规则。

## 三、核心业务规则

### 3.1 下单与服务范围

- **施工面积 ≤ 300㎡**：仅开放施工服务，不展示服务内容选择。
- **施工面积 > 300㎡**：页面即时展开服务内容，可选择「施工」或「仅代办」；代办审图、代办申报可多选，与施工组合形成组合服务。
- **图纸强制**：创建时必须上传初始施工图纸，支持多图上传，作为图纸深化与工作量拆解依据（原型上传组件为静态示意，必传校验为「原型未实现」）。
- **施工位置强制**：必须填写楼层、铺位号、店铺名称；列表与详情以「楼层 + 铺位 + 店铺名称」作为主标题，项目名称作为副文本。
- **客户核心信息**：客户名称（企业名称）、企业邮箱必填；员工代客户创建时，还须填写联系人、联系电话、电子邮箱。
- **店面唯一性校验**：同一建筑项目下，在途服务单（服务中、待确认）的店面编号不可重复；已完结、已结束、已终止的历史服务单不拦截。重复时提示联系管理员调整，或展示脱敏手机号引导切换账号（「原型未实现」；当前数据模型无独立店面编号字段，正式实现需补 `shopNo`）。
- **服务单编号**：系统按业务规则生成唯一编号（示例格式 `FW20260922001`），列表与详情保持一致。

### 3.2 项目匹配与创建流转

- **已收录项目**：项目选择页仅展示后台已配置跟进团队的项目。客户选择后，提交即按项目配置自动流转至绘图员「图纸深化」。
- **未收录/自定义项目**：客户通过「自定义项目 → 地图选点」录入项目。地图支持点选任意位置落点，或点击已有 POI 自动带出名称与地址；名称、地址、项目类型可修改。提交后服务单进入「评估指派」节点，在全体项目经理待办中可见。
- **项目经理评估指派**：项目经理线下沟通并完成现场勘验后，填写勘验时间、勘验结论（必填）、指派绘图员与指派说明；未填勘验结论不可提交。指派后进入「图纸深化」。
- **员工创建**：视为线下已完成沟通评估。员工补全客户信息并选择绘图员，提交后直接进入「图纸深化」，不经过评估指派。
- 创建页不展示项目跟进团队配置信息；项目配置仅在后台维护。

### 3.3 合同签订规则

- 报价员在「确认合同」节点或服务进行中补充签订合同。
- 合同服务项：仅代办、仅施工、完整施工代办。
- **可签订两次**：先签「仅施工」，后续可补签「仅代办」；先签「仅代办」，后续可补签「仅施工」。已签服务项置灰不可重复选择；「完整施工代办」一次覆盖两类服务。
- **工作量确认**：仅含施工服务的合同必须确认工作量。可采用绘图员提交版本，或线下重勘后上传最终深化图纸与工作量清单；最终确认版追加至绘图员过程文件。
- **合同要素**：合同附件、报价单附件、合同总价（选填）、备注、下一节点接收用户。
- 合同总价输入后即时转换为人民币大写展示；仅报价员本表单与财务视图可见完整金额。
- 下一节点接收用户按合同服务项限定：含代办 → 代办人员；仅施工 → 项目经理。
- 提交后生成合同记录与收款项目；服务节点按已签合同类型动态生成或追加。
- 报价员节点在首份合同确认提交后即结束：节点推进至下一服务节点，第二份合同为服务中并行补签，不阻塞主链路；若只签一类且未补签，则按该类合同对应节点推进。

### 3.4 合同收款规则

- 合同收款为并行支线，不受当前服务节点限制。合同签订后即可由财务人员收款。
- 财务人员可多次填写「本次填写后累计收款比例」与本次收款金额，保留每次收款记录。
- 单合同服务单显示一份收款项目；多合同服务单按合同分别确认，每份合同独立计算比例。
- 单份合同累计比例达到 100% → 该合同收款完成；全部已签合同达到 100% → 收款支线完结。
- 不跟踪付款方式、首付比例等合同约定，仅以累计收款比例为准。
- 服务单最终状态：服务支线完结且收款支线完结 → 已完成；尚未满足时保持「服务中」，并在详情页提示待完成支线。服务单创建即进入「服务中」，节点提交、推进均不写入「待处理」；「待处理」是当前节点处理人可见的派生处置态，详见 7.4 与附录 B.1、B.2。
- 财务工作台口径：
  - 首卡「待收款」：存在未收齐合同的服务单数量。
  - 第二卡「服务中」：财务可见服务单中持久状态为「服务中」的数量。
  - 待收款列表卡片仅显示「待收款」标签，不展示主流程状态标签。
  - 服务单列表中，财务视角隐藏「待处理」筛选；进行中服务单显示「服务中」，并叠加「待收款」或「已收讫」。
  - 已收讫指全部已签合同收款 100%。
  - 所有具备财务权限的用户看到一致的服务单范围与「待收款 / 已收讫」口径，任一财务用户均可完成收款，不存在「仅指定财务处理人可见」的情况。

### 3.5 结束服务与会签规则

- **入口范围**：所有员工处置节点均提供弱化样式的「结束服务」入口（虚线红边），统一替代角色专属终止操作。客户不可发起。
- **发起条件**：服务单持久状态为「服务中」，当前用户处于本人处置节点，且该服务单未发起过结束服务。
- **结束原因**：必填。
- **会签人**：项目经理 + 报价员。
  - 发起人为项目经理：本人默认确认，仅需选择报价员用户。
  - 发起人为报价员：本人默认确认，仅需选择项目经理用户。
  - 发起人为其他岗位：需分别选择项目经理与报价员用户，双方均需确认。
- **状态流转**：提交后服务单进入「待确认」；双方确认后进入「已结束」，生成结束服务记录。
- **会签待办**：项目经理、报价员工作台提供「待我会签」统计与橙色高亮区；列表卡片显示「待我会签 / 结束服务会签中」标签与橙色描边。
- **不可重复**：同一服务单不可重复发起结束服务；待确认、已结束、已完成、已终止状态不可发起。
- **详情展示**：详情页展示结束服务横幅，包含结束原因、发起人、双方确认状态与确认时间；已结束服务单展示完整结束记录。
- **与取消、终止的区分**：客户在深化前取消 → 已终止；历史已终止服务单保持只读；员工发起并经会签结束 → 已结束，二者不可混用。

### 3.6 撤回与取消规则

- **撤回（员工）**：当前节点已提交至下一节点，且下一节点尚未处理时，上一节点处理者可撤回；撤回需二次确认，撤回后节点回到待处理，可重新提交。下一节点已处理时撤回不可用。
- **取消（客户）**：客户创建服务单后、绘图员尚未开始图纸深化时可取消；二次确认后服务单终止，不可恢复。
- 撤回与取消均不影响已发生的合同、收款与结束服务记录。

### 3.7 状态与标签口径

服务单持久状态 5 类；「待处理」是节点处置态，不写入服务单持久状态：

| 状态 | 含义 | 视觉 |
|---|---|---|
| 服务中 | 服务单创建即进入，直至完成、结束或终止 | 浅蓝 |
| 待确认 | 结束服务已发起，等待项目经理/报价员会签 | 深橙描边 + 标签 |
| 已完成 | 服务支线完结且全部合同收款 100% | 浅绿 |
| 已结束 | 结束服务会签完成 | 浅紫 |
| 已终止 | 客户取消或历史终止 | 浅红 |

> 「待处理」为派生处置态：仅当前节点处理人可见（浅橙）；客户、财务及其他非当前处理人显示「服务中」。财务视角统一按「服务中」展示，并以「待收款 / 已收讫」表达收款支线；映射规则见 7.4 与附录 B.2。

关键标签：

| 标签 | 展示对象 | 含义 |
|---|---|---|
| 待我会签 / 结束服务会签中 | 项目经理、报价员；列表与详情 | 有待本人确认的结束服务申请 |
| 待我指派 / 待指派 | 项目经理；列表与详情 | 客户自定义项目等待评估指派 |
| 待确认合同（小程序）/ 待补签合同（Web） | 报价员 | 可补充签订第二份合同 |
| 待收款 | 财务视图 | 存在未收齐合同（通用列表不展示该标签） |
| 已收讫 | 财务视角服务中服务单 | 全部合同收款 100% |
| 待我处理 | Web 端当前节点处理人 | 派生标签，表示服务单待本人处置；管理员与财务不展示 |
| 已结束服务 | Web 端项目经理 / 报价员 | 本人参与的结束服务会签已完成 |
| 可撤回 | 员工列表 | 满足撤回条件 |
| 金额已脱敏 / 总价已脱敏 | 非财务、非报价员合同表单 | 金额不可见 |

### 3.8 金额脱敏规则

- 统一判断：仅财务人员视图与报价员「确认合同」表单可展示完整金额。
- 合同卡片：财务显示「总价 ¥xxx」，其他角色显示「总价已脱敏」；未填写显示「总价未填写」。
- 收款记录：财务显示金额与大写，其他角色显示「金额已脱敏」，比例始终可见。
- 节点文件区、操作历史、通知内容同样遵循脱敏规则。

### 3.9 下一节点接收用户

- 员工创建、提交图纸、审核通过、确认合同、更新施工量等推进表单末尾均提供「下一节点接收用户」。
- 系统按项目配置预选负责人，提交人可切换同角色其他用户（原型为静态人员列表，项目预选待实现）。
- 确认合同按合同服务项限定范围：含代办 → 代办人员；仅施工 → 项目经理。
- 更新施工量按是否含代办申报预选：含申报 → 代办人员；否则 → 项目经理。
- 客户创建节点不展示接收用户选择，按项目配置或共享池自动流转。

### 3.10 消息通知与超时

- 通知类型：节点推进通知、超时预警、超时告警、结束服务会签提醒。
- 推送渠道：应用内消息、小程序推送、邮件（可按通知类型配置）。
- 超时采用接收时限、预警时限、告警时限三级阈值。
- 超时告警推送至当前节点处理人及该业务前置节点内部处理人，自动去重，排除客户。
- 消息中心按「全部 / 进度通知 / 预警通知」分类，未读消息显示红点。

### 3.11 节点版本与留痕

- 每个节点提交生成版本记录，包含操作人、时间、版本号、表单内容、附件与处理结果。
- 客户仅查看节点最终生效版本；员工查看本人负责节点版本；系统管理员查看全量版本。
- 合同两次签订、收款多次记录、结束服务会签、撤回、取消均需留痕。
- 版本记录与操作历史在服务单详情中按时间轴展示。

## 四、微信小程序端功能需求

### 4.1 登录与信息补全

- 微信手机号授权登录；授权后按手机号匹配客户/员工身份（原型以角色 Tab 模拟登录，授权与匹配未模拟）。
- 客户首次登录进入信息补全页：客户名称（企业名称）、电子邮箱必填，提交后进入客户工作台。
- 员工登录直接进入员工工作台。
- 个人中心支持查看姓名、角色，退出登录（原型未展示手机号，手机号展示为「原型未实现」）。

### 4.2 客户工作台

- 欢迎区与消息入口。
- 「创建服务单」卡片。
- 服务单列表按进行中、已完成、已终止分 Tab；进行中统一显示「服务中」，不展示内部「待处理」。
- 空态：进行中 Tab 显示「暂无进行中的服务单」，其他 Tab 显示「暂无服务单」，均提供创建入口。

### 4.3 员工工作台

- 身份区显示姓名与角色，提供消息入口。
- 员工可创建服务单，入口受后台角色权限控制（当前默认开启）。
- 统计卡：员工通用为待处理、服务中（待处理为当前节点由本人处置的派生数量）；项目经理与报价员增加「待我会签」；财务人员首卡为「待收款」、第二卡为「服务中」。
- 待办区：
  - 项目经理：待我评估指派（客户自定义项目）蓝色高亮区。
  - 报价员：待补充合同（第二份合同）蓝色高亮区。
  - 项目经理/报价员：待我会签（结束服务）橙色高亮区。
  - 待我处理列表：财务视角合并为「待收款」口径，展示未收齐合同的服务单与收款比例；卡片仅显示「待收款」标签。
- 空态：员工无待办显示「暂无待我处理的服务单」；财务无待收款显示「暂无待收款的服务单」。

### 4.4 创建服务单

- 项目选择：展示已配置跟进团队的项目，支持搜索；提供「自定义项目」入口。
- 自定义项目：地图选点或点击 POI 带出名称/地址，可修改名称、地址、项目类型；名称或地址为空时不可确认。
- 施工位置：楼层、铺位号、店铺名称。
- 施工面积：输入超过 300㎡ 即时展开服务内容。
- 服务内容：施工 / 仅代办；代办审图、代办申报可多选。
- 初始图纸：必传，支持多图。
- 员工端：增加客户信息区（客户名称、联系人、联系电话、电子邮箱，均必填）与服务指派区（默认绘图员，可切换）。
- 提交结果：已收录项目自动流转绘图员；自定义项目进入评估指派；员工创建直接进入图纸深化。

### 4.5 服务单列表

- 筛选：状态（含待确认、已结束）、节点。
- 卡片主标题为施工位置，副信息为项目、客户；展示编号、状态、当前节点、更新时间。
- 标签：待我会签、结束服务会签中、待我指派、待指派、待确认合同（小程序）/ 待补签合同（Web）、待收款、已收讫、可撤回；「待我处理」「已结束服务」为 Web 端标签，小程序列表卡片不展示。
- 客户与财务视角不展示「待处理」筛选项；其他员工保留该筛选项，但筛选与卡片使用同一查看者解析口径——仅当前节点由本人处置的服务单命中「待处理」，其余在途服务单显示为「服务中」，不会出现在「待处理」筛选结果中。
- 财务视角进行中统一显示「服务中」，并叠加「待收款」或「已收讫」。
- 列表展示 23 条示例服务单，覆盖全部状态。

### 4.6 服务单详情

- 状态头：施工位置为主标题，项目名称与类型为副文本；展示编号与状态标签。
- 评估指派横幅：项目经理操作提示或客户等待勘验说明。
- 结束服务横幅：会签中/已结束状态、结束原因、发起人、双方会签状态与时间。
- 全流程进度条：基础节点 + 按已签合同动态生成的审图、施工、申报、验收节点；合同收款作为并行支线展示。
- 合同与收款卡片：单合同/多合同、逐份收款进度、服务与收款并行状态；合同总价按角色脱敏。
- 基础信息卡：项目、施工位置、面积、客户、联系方式、服务项、当前处理人、创建时间。
- 节点文件区：按节点折叠；已完成节点展示提交人、时间、版本号、表单记录与附件；当前节点展示等待处理提示；确认合同节点展示两次合同信息。
- 底部操作栏：按角色与节点展示操作，并统一提供弱化「结束服务」入口。

### 4.7 确认合同

- 合同服务项：仅代办 / 仅施工 / 完整施工代办；已签类型置灰。
- 工作量确认：含施工服务的合同需选择采用绘图员版本，或上传最终确认版并追加至过程文件。
- 合同附件、报价单附件、合同总价（选填，自动转大写）、备注、下一节点接收用户。
- 提交后生成合同与收款项目，并按合同类型生成/追加服务节点。
- 报价员在服务进行中可点击「继续确认合同」补签另一类合同。

### 4.8 节点操作弹窗

| 弹窗 | 操作角色 | 关键内容 |
|---|---|---|
| 评估并指派 | 项目经理 | 勘验时间、勘验结论（必填）、指派绘图员、指派说明 |

| 施工量更新 | 项目经理 | 施工时间、本次完成施工量、施工说明、下一节点接收用户 |
| 提交验收 | 项目经理 | 验收文件、验收说明；提示收款由财务并行跟进 |
| 合同收款确认 | 财务人员 | 按合同列示收款项目、累计比例、收款金额、收款记录 |

| 撤回确认 | 员工 | 二次确认，撤回后回到待处理 |

| 结束服务申请 | 员工 | 结束原因、会签人选择；弱化提交按钮 |
| 结束服务会签确认 | 项目经理/报价员 | 结束原因、发起信息、双方会签进度、确认会签 |

### 4.9 消息与个人中心

- 消息分类：全部 / 进度通知 / 预警通知；未读红点；支持查看详情。
- 个人中心：个人信息、消息、设置、关于、客服、退出登录。

### 4.10 通用体验要求

- 状态色、标签、金额脱敏、空态文案双端一致。
- 所有提交类操作需校验必填项并给出错误提示。
- 危险操作（结束服务、取消、终止）使用弱化或二次确认样式，不得使用高亮主按钮。
- 地图、文件上传在原型阶段为静态示意，正式实现需接入真实服务。

## 五、Web 管理后台功能需求

Web 管理后台以「管理闭环」为目标：小程序端产生的项目、账号、服务单、合同、收款、结束服务与通知数据，均可在后台完成配置、监控、干预与审计。

### 5.1 登录与概览驾驶舱

- 系统管理员账号密码登录；错误提示校验失败。
- 驾驶舱指标卡：工单总量、在途工单、完结工单、超时工单。
- 近 7 日新增工单趋势、服务类型占比。
- 超时与预警待办列表，可跳转服务单详情。
- 指标口径与小程序端、统计报表保持一致。

### 5.2 项目点位管理

- 项目列表：按名称/地址搜索，按启用、停用、临时筛选；展示类型、地址、负责人、工单数、状态。
- 新增项目：官方名称来自地图点选，可补充别名、类型、地址；初始为临时状态（原型中别名、类型、地址为只读展示，编辑提交为「原型未实现」）。
- 项目详情：基础信息、专属服务团队配置（绘图员、项目经理、报价员、财务人员、代办人员、施工人员），支持按岗位选择负责人。
- 项目操作：保存、停用、临时项目转正；停用后不可新增服务单，在途服务单不受影响；保存后提示在途工单同步新流转规则。
- 项目配置直接影响小程序端已收录项目列表、自动流转与下一节点接收用户预选。

### 5.3 账号管理

- **员工账户**：新增、编辑、停用、启用；字段包含姓名、岗位、部门、手机号；支持按姓名/手机号搜索与岗位筛选。停用后员工无法登录小程序，名下待办退回共享工作池。
- **业主信息**：按姓名/手机号/邮箱搜索与状态筛选；展示姓名、手机号（默认脱敏）、企业邮箱、关联服务单数、状态；支持修正信息、停用、启用。手机号与邮箱变更需短信校验并留痕（原型仅展示提示文案，校验与留痕为「原型未实现」）。
- 员工岗位与节点处置权限的绑定关系在「岗位配置」维护；项目团队人员从员工账户中选择。

### 5.4 服务单全量管理与工作推进

- **列表**：按编号/施工位置/客户搜索，按状态、节点、项目筛选；表格展示编号、施工位置、项目、客户、当前节点、状态、更新时间；分页。
- **详情**：状态头、全流程进度、基础信息、节点版本记录时间轴、操作历史；展示评估指派记录、结束服务会签记录、合同与收款信息。
- **工作推进**：Web 端与服务端共用小程序同一套节点规则、表单与校验。具备对应岗位权限的用户可在 Web 执行节点操作；系统管理员可查看全量，但不得绕过会签、金额脱敏与状态约束。
- **共享池与分派**：服务单列表提供「共享池」开关筛选；管理员可将共享池工单分派给具体员工，分派结果同步至员工待办。员工主动拾取、管理员回收至共享池均为「后续规划」，原型未提供入口。
- **结束服务**：Web 端支持查看待确认/已结束服务单及会签记录；项目经理/报价员在 Web 端也应能处理「待我会签」，确认规则与小程序一致。
- **合同与收款**：Web 端支持查看两份合同、逐份收款进度与收款记录；具备财务岗位权限的用户可更新累计收款比例与金额；非财务人员金额脱敏。
- **审计**：节点版本、撤回、取消、结束服务、合同补签、收款更新均保留操作人、时间与内容。
- **筛选与标签**：状态筛选覆盖 5 个持久状态及当前处理人可见的派生「待处理」（含待确认、已结束），另支持节点、项目、共享池筛选；财务与管理员不提供「待处理」筛选项；待收款、已收讫、待我会签为标签口径，不作为独立筛选项（原型未提供）。

### 5.5 流程编排

- 按服务类型切换分支：纯施工、纯代办、组合服务。
- 可视化节点流：创建、评估指派（可选）、图纸深化、审核、确认合同、审图（可选）、施工、申报（可选）、验收办结；合同收款以并行支线展示。
- 节点处置权限：展示权限名称与已绑定岗位；点击节点可跳转岗位配置绑定。
- 节点级超时规则：选中节点后配置启用开关、时限单位（小时 / 工作日）、接收时限、预警时限、告警时限，支持「应用到全部节点」。同一节点在不同服务分支共用一份阈值；创建节点不参与超时监控。
- 保存校验：时限为正整数且满足 接收 ≤ 预警 ≤ 告警；不合法时拦截并提示具体节点。
- 保存后提示新服务单按新规则执行；已进入节点并生成时限的服务单保持原时限、不重算，新进入节点按新阈值计算。
- 超时阈值的推送范围、频次与渠道不在本页配置，统一由 5.7「通知与超时」按「节点 × 事件」维护，本页只定义「什么时候算超时」。

### 5.6 岗位配置

- 岗位列表：内置岗位 + 自定义岗位；展示已绑定权限数量。
- 新增岗位、删除自定义岗位（二次确认）。
- 权限绑定：按节点勾选处置权限，权限名称自动按节点操作命名。
- 岗位权限变更后，流程编排中「可处置岗位」与员工待办同步更新。

### 5.7 通知与超时

- 配置范围：通用事件 + 各业务节点（不含创建节点），按「节点 × 事件」配置推送策略。
- 通知事件 8 类：节点待处理、节点已提交、审核驳回、收款提醒、超时预警、超时告警、结束服务会签、结束服务完成；其中审核驳回仅审核节点、收款提醒仅合同收款节点，会签与会签完成为整单级通用事件。
- 渠道：每条事件分别配置应用内、小程序、邮件开关；开启邮件时必须选择该事件的邮件模板。
- 收件人：按岗位 / 角色多选（节点处理人、前置节点处理人、项目经理、绘图员、报价员、财务、创建人、相关员工、客户、运营抄送），系统按服务单与项目专属团队解析并自动去重；客户仅接收进度类事件（节点已提交、结束服务完成），超时告警强制排除客户。
- 频次：超时预警仅推送 1 次；超时告警每 24 小时 1 次、最多 3 次，去重键为服务单 + 节点 + 事件。
- 超时阈值来源：只读展示流程编排中该节点的接收 / 预警 / 告警时限，提供跳转入口，不在本页重复录入。
- 兜底：节点无处理人（岗位空缺或项目未配置团队）时按「项目经理 → 系统管理员」升级，避免通知丢失。
- 保存校验：启用的事件至少一个渠道、收件人不能为空、邮件渠道必须有模板；通过后即时生效，已发送记录不追溯。
- 模板预览随「节点 + 事件 + 模板」联动；发送记录查询与失败重试为「原型未实现 / 后续规划」，见附录 D。

### 5.8 统计报表

- 指标卡：工单总量、在途工单、完结工单、完结率。
- 维度切换：服务类型、项目；时间范围：近 6 个月、本年度。
- 图表：各维度工单量柱状图、月度趋势折线图。
- 明细表：服务类型、工单量、占比、在途、完结。
- 导出报表：按当前筛选条件导出，导出行为留痕（原型按钮为静态示意，导出与留痕为「原型未实现」）。

| 能力 | 小程序端 | Web 管理后台 | 一致性要求 |

## 六、关键机制说明

### 6.1 评估指派机制

- 仅客户创建且项目未配置跟进人员（自定义/未收录项目）时触发。
- 服务单进入全体项目经理可见的待指派池，列表显示「待指派」。
- 项目经理完成现场勘验并填写必填结论后指派绘图员；指派后节点进入图纸深化。
- 员工创建视为已完成线下评估，不经过该节点。

### 6.2 合同两次签订与动态节点机制

- 首次签订后记录合同类型；未签的另一类可补签。
- 已签类型置灰，避免重复合同。
- 节点按合同类型与所选代办项生成：仅施工 → 施工/验收；仅代办 → 所选审图/申报节点；完整施工代办 → 审图（如选）/施工/申报（如选）/验收。
- 补签后追加对应节点，不重复生成已有节点；节点流转顺序始终遵循完整流程：审图 → 施工 → 申报 → 验收办结（合同收款为并行支线）。
- 补签回退规则：新增节点位置早于当前节点的，服务单回退至这些节点中最早的一个（按完整流程顺序，跳过已完成节点），当前节点转为该新增节点，处理人取报价员确认合同时所选接收用户。
- 回退链内新增节点依次流转，不弹「下一节点接收用户」；最后一个新增节点完成后自动流回原节点、原处理人，原节点处置进度保留（如项目经理施工量已更新进度）。
- 新增节点位置晚于当前节点的，不回退，按完整流程顺序正常追加为待处理节点。
- 原节点在回退期间展示为「待回办 · 进度保留」，不可操作；回流后恢复为当前节点。回退前已完成的节点保持「已完成」，不回退重办。
- 回流到原节点后继续推进时，恢复常规「下一节点接收用户」选择。双端原型以 `rollback`（回退上下文）+ `completedNodes`（回退前已完成节点）实现，示例见附录 C.2 AC-14。
- 补签发生在结束服务会签（待确认）期间时禁止补签，提示先完成会签。
- 工作量差异通过「采用绘图员版本」或「上传最终确认版」解决，最终版追加至绘图员过程文件，不回流绘图员节点。

### 6.3 收款并行与办结判定机制

- 合同生成即创建收款项目，财务可并行更新。
- 收款不阻塞施工/代办节点，施工/代办完结也不自动办结服务单。
- 单份合同 100% → 该合同完成；全部合同 100% 且服务支线完结 → 已完成。
- 任一条件未满足时，服务单保持「服务中」，详情页明确提示待完成支线。

### 6.4 结束服务会签状态机

```text
服务中（创建即进入）
  → 员工发起结束服务（原因必填）
  → 待确认（会签中）
      → 双方确认 → 已结束（生成结束记录）
      → 任一方未确认 → 保持待确认
```

- 发起人本人默认确认；另一方或其他岗位发起时按规则选择会签人。
- 待确认状态不可再次发起结束服务，也不可执行普通节点推进。
- 已结束服务单只读，保留完整会签、原因与时间记录。

### 6.5 金额脱敏机制

- 服务端统一返回脱敏后的金额字段与完整比例字段；前端按角色渲染。
- 仅财务角色与报价员确认合同表单请求完整金额。
- 导出、通知、日志、节点文件均执行同一脱敏策略。
- 系统管理员默认不查看完整金额；如需查看，应由财务角色授权并留痕（原型未实现）。

### 6.6 超时告警机制

- 三级阈值：接收时限、预警时限、告警时限。
- 到达预警时限发送预警；到达告警时限发送告警。
- 推送范围可配置，默认当前节点处理人；告警可扩展至前置节点处理人。
- 推送渠道与频次按通知配置执行；发送记录留存为「原型未实现」。

### 6.7 项目地图匹配机制

- 项目创建与客户自定义项目均接入地图服务，支持点选建筑或 POI 拉取名称与地址。
- 后台项目以官方名称为匹配键，别名仅用于内部检索。
- 已收录项目供客户直接选择；未收录项目由客户自定义创建，后台可转正并补全团队。

### 6.8 共享工作池机制

- 按岗位划分，仅对应岗位员工可见；原型中主要表现为项目经理「待指派池」与管理端「共享池」。
- 原型支持项目经理评估指派与管理员分派，分派后进入个人待办；员工主动拾取、退回共享池为「后续规划」。
- 账号停用、无配置负责人时自动回流为「原型未实现」（当前仅展示提示文案）。
- 共享池工单同样受接收时限、预警时限与告警时限约束。

## 七、流程与节点权责

### 7.1 节点权责总表

| 节点 | 触发/操作角色 | 关键动作 | 流转去向 |
|---|---|---|---|
| 创建 | 客户 / 员工 | 选择项目、填写位置面积、上传图纸、选择服务内容 | 已收录项目→绘图员；自定义项目→评估指派；员工创建→绘图员 |
| 评估指派（可选） | 项目经理 | 现场勘验、填写结论、指派绘图员 | 图纸深化 |
| 图纸深化 | 绘图员 | 上传深化图纸、工作量清单 | 审核 |
| 审核 | 项目经理 | 审核通过 / 驳回 | 通过→确认合同；驳回→图纸深化 |
| 确认合同 | 报价员 | 确认合同、工作量、附件、总价、下一节点接收用户 | 按合同类型生成服务节点；合同收款并行生成 |
| 审图（可选） | 代办人员 | 上传审图凭证 | 施工（完整合同）或申报（仅代办） |
| 施工 | 项目经理 | 更新施工量 | 申报（含申报）或验收办结 |
| 申报（可选） | 代办人员 | 上传申报凭证 | 验收办结（含施工）或代办服务完结（仅代办） |
| 验收办结 | 项目经理 | 上传验收文件与说明 | 服务支线完结 |
| 合同收款（并行） | 财务人员 | 多次填写累计比例与金额 | 全部合同 100% → 收款支线完结 |
| 结束服务 | 任一员工 | 填写原因、选择会签人 | 待确认 → 已结束 |

### 7.2 三类合同节点分支

| 合同类型 | 节点序列 |
|---|---|
| 仅施工 | 确认合同 → 施工 → 验收办结 |
| 仅代办 | 确认合同 → 审图 / 申报（按所选代办项生成）→ 代办服务完结 |
| 完整施工代办 | 确认合同 → 审图（如选）→ 施工 → 申报（如选）→ 验收办结 |

两份合同分别签订时，服务节点取并集；例如先签仅施工、补签仅代办且只选审图，则节点为审图 → 施工 → 验收办结（未选的代办项不生成）。

### 7.3 结束服务流程

| 步骤 | 操作角色 | 规则 |
|---|---|---|
| 发起 | 当前节点员工 | 结束原因必填；不可重复发起 |
| 选择会签人 | 发起人 | PM 发起选报价员；报价员发起选 PM；其他岗位分别选 PM 与报价员 |
| 会签 | 项目经理、报价员 | 双方确认后结束；发起人本人默认确认 |
| 结束 | 系统 | 状态变为已结束，生成结束服务记录并留存 |
| 通知 | 系统 | 通知发起人、会签人及服务单相关员工 |

### 7.4 状态流转

| 当前状态 | 触发 | 目标状态 |
|---|---|---|
| — | 服务单创建 | 服务中（创建即服务中，不写入待处理） |
| 服务中 | 员工提交当前节点 | 服务中（仅推进 `currentNode`；下一节点处理人看到派生「待处理」） |
| 服务中 | 服务支线 + 收款支线均完结 | 已完成 |
| 服务中 | 员工发起结束服务 | 待确认 |
| 待确认 | 双方会签完成 | 已结束 |
| 待确认 | 普通节点操作 | 不允许 |
| 服务中 | 客户取消（深化尚未开始） | 已终止 |
| 服务中 | 补签合同且新增节点早于当前节点 | 服务中（回退至新增节点，完成后自动回流原节点并保留进度） |

> 查看者状态展示：当前节点处理人看到派生「待处理」，其他员工、客户、财务与系统管理员看到「服务中」；财务另以「待收款 / 已收讫」表达收款支线。详见附录 B.2。

### 7.5 下单校验项

| 校验项 | 规则 | 异常处理 |
|---|---|---|
| 建筑项目 | 已收录项目可选；未收录需自定义 | 未选项目不可提交 |
| 施工位置 | 楼层、铺位号、店铺名称必填 | 缺失不可提交 |
| 施工面积 | 数值必填；>300㎡ 展开服务内容 | 缺失不可提交 |
| 初始图纸 | 必传 | 未上传不可提交（原型未校验） |
| 服务内容 | >300㎡ 可选施工/仅代办；≤300㎡ 仅施工 | 未选择不可提交 |
| 客户核心信息 | 客户名称、企业邮箱必填；员工创建补充联系人、电话、邮箱 | 缺失不可提交 |
| 店面唯一性 | 同项目在途服务单店面编号唯一 | 重复时提示联系管理员或切换账号（原型未实现，需补独立店面编号字段） |

## 八、非功能与验收

### 8.1 非功能要求

- **性能**：常用列表、详情接口在正常网络下 2 秒内返回；列表分页加载。
- **安全**：手机号、邮箱等敏感信息加密存储与传输；金额按角色脱敏；操作日志、导出日志、登录日志留存。
- **兼容**：小程序适配主流微信版本与常见机型；Web 适配主流桌面浏览器，最小 1280px 宽度。
- **可用性**：危险操作弱化展示并二次确认；关键状态与金额脱敏不可被前端绕过。
- **数据一致性**：双端读写同一业务数据；节点、合同、收款、会签状态变更需事务化处理。

### 8.2 验收清单

1. 客户选择已收录项目提交后，服务单自动流转至项目绘图员，服务单立即为「服务中」，当前节点处理人显示「待处理」，客户视角仅显示「服务中」。
2. 客户通过自定义项目 + 地图选点创建后，服务单进入项目经理「待我指派」，填写勘验结论并指派后进入图纸深化。
3. 员工创建服务单可直接指派绘图员，不出现评估指派节点。
4. 绘图员提交图纸与工作量，项目经理可审核通过或驳回；驳回后回到图纸深化。
5. 报价员可签订仅施工、仅代办或完整施工代办合同；先签一类后可在服务中补签另一类；已签类型置灰。
6. 含施工合同可确认工作量，采用绘图员版本或上传最终确认版并追加至过程文件。
7. 财务可多次更新收款比例；多合同分别确认；全部合同 100% 且服务完结后服务单已完成。
8. 财务工作台首卡为待收款，第二卡服务中数量不小于待收款；所有财务权限用户均可查看并完成收款；服务单列表隐藏待处理筛选，显示待收款/已收讫。
9. 任一员工处置节点可发起结束服务；原因必填；PM/报价员发起时本人默认确认；双方确认后状态为已结束并生成记录。

### A.4 通用约定

- 基础路径 `/api/v1`，统一响应 `{ code, message, data, requestId }`；列表为 `{ items, total, page, pageSize }`。
- 时间统一 `Asia/Shanghai` 存储与计算，接口返回 ISO 8601；金额以分为单位整数传输，比例用 0–100 整数。
- 节点操作必须携带 `version` 与 `Idempotency-Key`；服务端校验版本，冲突返回 `40901` 并提示刷新。
- 脱敏在服务端完成：非授权角色返回 `totalPrice: null`、`amount: null`，同时返回 `masked: true`；前端不得自行还原。
- 错误码：`40001` 参数校验、`40101` 未登录、`40301` 无权限、`40302` 越权查看金额、`40401` 资源不存在、`40901` 状态冲突、`40902` 重复提交、`42201` 业务规则不满足、`50001` 系统异常。

## 附录 B 状态机与权限/校验矩阵

### B.1 服务单状态机

| 事件 | 前置条件 | 状态变化 | 副作用 |
|---|---|---|---|
| 创建服务单 | 表单校验通过 | → 服务中 | 生成编号；进入绘图员或待指派池；产生待办与通知；当前节点处理人看到派生「待处理」 |
| 提交当前节点 | 必填项通过 | 保持服务中 | 生成节点版本；推进 `currentNode`；生成下一节点待办与通知；重置接收时限；下一节点处理人看到派生「待处理」 |
| 审核驳回 | 当前节点为审核 | 保持服务中 | `currentNode` 回退到深化；生成驳回版本与通知 |
| 补签合同 | 未签另一类且非待确认 | 保持服务中 | 追加合同与收款项目；新增节点位置早于当前节点时回退至新增节点（写 `rollback`，处置人取合同所选接收用户），完成后自动回流原节点并保留进度；晚于当前节点的按完整流程顺序追加 |
| 收款更新 | 财务权限用户 | 保持服务中 | 记录收款；单份合同 100% 标记收讫；所有财务用户共享该处置权 |
| 服务与收款均完结 | 两条支线均完成 | → 已完成 | 记录完结时间 |
| 发起结束服务 | 当前节点员工 | 服务中 → 待确认 | 冻结普通节点操作；通知 PM 与报价员 |
| 双方会签完成 | PM 与报价员均确认 | 待确认 → 已结束 | 生成结束记录；通知相关员工；服务单只读 |
| 客户取消 | 深化尚未开始 | 服务中 → 已终止 | 通知相关员工；不可恢复 |
| 员工撤回 | 下一节点未处理 | 保持服务中（节点回到待处理） | `currentNode` 回退；撤销对应节点版本 |

### B.2 查看者状态展示

服务单持久状态只有「服务中」；下表说明派生展示口径：

| 查看者 | 服务单处于服务中且当前节点归属本人 | 服务单处于服务中且当前节点归属他人 | 说明 |
|---|---|---|---|

## 附录 C 异常边界与验收用例

### C.1 异常与边界场景

| 场景 | 期望 |
|---|---|
| 两位处理人同时提交同一节点 | 版本校验失败方提示「服务单已更新，请刷新后重试」，不产生重复节点版本 |
| 撤回后再次提交 | 回到上一节点待处理；旧版本标记为已撤销，保留审计 |
| 补签发生在施工中 | 新增审图节点早于当前施工节点：服务单回退至审图，审图完成后按完整流程回到施工并保留施工进度；晚于当前节点的申报节点正常追加 |
| 补签发生在待确认 | 禁止补签，提示先完成会签 |
| 收款比例回退或超过 100 | 拒绝并提示；保留原记录 |
| 收款金额超过合同未收金额 | 拒绝并提示 |
| 合同未签完即发起结束服务 | 允许，但会签记录需说明；已完成合同与收款不变 |
| 客户取消时会签中 | 不允许，提示等待会签结果 |
| 员工账户停用 | 名下待办进入共享池（待实现）；历史操作记录保留 |
| 项目停用 | 不可新增服务单；在途服务单按原规则继续 |
| 自定义项目转正 | 已创建服务单绑定新项目；团队配置从转正时生效 |
| 通知重复触发 | 同一服务单同一事件在 5 分钟内去重；发送失败重试 3 次 |
| 文件上传中断 | 返回失败并保留已上传文件 id；不生成半成品节点版本 |
| 超时会签 | 超过告警时限后升级通知；不自动结束服务单 |

| 问题 | 原现状 | 影响 | 处理结果 |
|---|---|---|---|
| 组合服务跳过施工 | 审图提交后直接进入申报 | 施工节点可能漏办 | 已修复为审图→施工→申报，回归 AC-06 |
